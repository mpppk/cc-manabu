# プロンプトキャッシュの残り時間（#103）

Agent SDK 0.3.330 と、Claude サブスクリプションでログインした Claude Code で確認した（2026-11）。

## 取得できるもの

`includePartialMessages: true` の `stream_event` で、モデルリクエストごとに `message_start` が届く。
その `message.usage` にキャッシュの読み込み・書き込みと、書き込みの TTL ごとの内訳がある。

```json
{
  "input_tokens": 4,
  "cache_creation_input_tokens": 886,
  "cache_read_input_tokens": 1672,
  "cache_creation": { "ephemeral_5m_input_tokens": 0, "ephemeral_1h_input_tokens": 886 }
}
```

- サブスクリプションでは 1 時間の TTL で書き込んでいた（SDK の設定の説明でも、サブスクリプションは既定で 1 時間、API キーは 5 分）。
  `CLAUDE_CODE_PROMPT_CACHE_TTL` や設定で変えられる
- `result.usage` はターンの合算で、`iterations` にリクエストごとの値も入る。ただし開始時刻は無い
- リクエストの開始時刻そのものは取れない。`message_start` は送信の 0.5 秒ほど後に届いた
- サブエージェントのリクエストは `parent_tool_use_id` 付きで届く（メインの会話のキャッシュとは別）

## 推定方法

- メインの会話の `message_start` ごとに、直前に届いた SDK メッセージの時刻を「リクエストを送った時刻の下限」として記録する
  （`StreamMapper`。最初のリクエストは query を始める前の時刻）。期限を遅い方に見積もらないため
- ターンで最後のリクエストの観測値を、回答の metadata（`claudeCode.promptCache`）に保存する。ツールを使う長いターンでも、
  回答の完了時刻ではなく最後のリクエストの開始から数える
- 表示側（`src/web/lib/prompt-cache.ts`）で `期限 = 開始時刻 + TTL` を求め、毎秒数え直す。期限を時刻で持つのでリロード後も正しい
  - 書き込みが 1 時間だけなら 1 時間、5 分だけなら 5 分
  - 読み込みだけなら、それより前に書き込んだときの TTL で延長されたとみなす
  - 両方の TTL に書き込んでいる、TTL が分からない、キャッシュを使っていない、観測が無い（古い回答）ときは「不明」
  - 中断した回答は観測が残らないので、それより前のリクエストを使う（短めに見積もる）
  - 選んでいるモデルが最後の回答と違えば「不明」（キャッシュはモデルごと）
- 分岐は分岐ごとの履歴（引き継いだ回答を含む）から求める

あくまで目安で、次のリクエストでキャッシュが使われることは保証しない（画面のツールチップにもそう書く）。
